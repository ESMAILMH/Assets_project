# نظام حصر الأصول وتتبع العهد الشخصية

**كلية التقنيات الهندسية – يفرن | قسم تقنية المعلومات**
تطبيق ويندوز (C# / .NET 8 Windows Forms) مع قاعدة بيانات **SQL Server** عبر **ADO.NET**،
مبني على وثيقة التحليل وقاعدة البيانات `AssetsDB` (12 جدولاً).

## التشغيل

1. افتح الملف `Database/01_AssetsDB.sql` في SSMS من **File ← Open ← File** (لا تنسخ النص من صفحة GitHub) واضغط Execute.
   ينشئ قاعدة `AssetsDB` بالجداول والعروض والإجراءات المخزنة.
   > إذا ظهرت أخطاء مثل `There is already an object named ...` فهذا يعني أن الجداول أُنشئت سابقاً في قاعدة master:
   > شغّل `Database/00_Cleanup.sql` مرة واحدة، ثم أعد تشغيل `01_AssetsDB.sql`.
2. *(اختياري)* شغّل `Database/02_SampleData.sql` لإضافة بيانات تجريبية كاملة
   (5 أقسام، 8 مواقع، 8 أشخاص، 23 أصلاً، عهد مفتوحة ومنتهية، صيانة، تخريد، جرد) مع حسابات دخول:
   `admin / Admin@123` (مدير) — `store / Store@123` (أمين مخزن) — `user / User@123` (موظف).
   ثم *(اختياري)* `Database/03_SampleImages.sql` لإضافة صور توضيحية للأصول التجريبية.
3. افتح `AssetTracking.sln` في Visual Studio 2022 واضغط **F5**.
4. **أول تشغيل:** يطلب التطبيق إنشاء حساب **المدير** (كلمة المرور تُشفَّر في C# ثم تُحفظ).
5. إذا كان اسم الخادم غير `.\SQLEXPRESS` عدّله من **إعدادات الاتصال** في شاشة الدخول، أو من `appsettings.json`.

المتطلبات: Windows 10 أو أحدث، Visual Studio 2022، .NET 8، SQL Server (Express يكفي).
الحزم: `Microsoft.Data.SqlClient` (ADO.NET) و `ClosedXML` (Excel) — تُحمَّل تلقائياً من NuGet.

## تعديل الشاشات من المصمم (Designer)

كل شاشة مكوّنة من ملفين:
- `اسم_الشاشة.cs` ← المنطق (الأحداث، التحميل، الحفظ). اضغط عليه **دبل كليك** فيفتح **المصمم**.
- `اسم_الشاشة.Designer.cs` ← تصميم العناصر وأماكنها (يكتبه المصمم تلقائياً، لا تعدّله يدوياً).

في المصمم يمكنك سحب العناصر وتغيير أحجامها ونصوصها وألوانها من نافذة **Properties**.
ملاحظات:
- النوافذ مضبوطة على **من اليمين لليسار** (`RightToLeftLayout = true`)، لذلك قيمة `X` تُحسب من الحافة اليمنى.
- **لا تغيّر أسماء العناصر** (`Name`) المستخدمة في الكود مثل `txtName` و `cmbDepartment` و `grid`، وإلا يجب تعديلها في ملف المنطق أيضاً.
- تنسيق الجداول (الألوان وارتفاع الصفوف) يُطبَّق عند التشغيل، لذلك يظهر الجدول بسيطاً داخل المصمم.
- بطاقات الشاشة الرئيسية ومحتوى تبويبات «الأقسام والمواقع والتصنيفات» تُنشأ عند التشغيل لأنها من قاعدة البيانات.
- أزرار القائمة الجانبية كلها ظاهرة في المصمم، ويُخفى منها ما لا يسمح به دور المستخدم عند التشغيل. كل زر يحمل في `Tag` اسم صفحته.

## هيكل المشروع (ثلاث طبقات)

```
AssetTracking/
├── Database/
│   ├── 01_AssetsDB.sql        قاعدة البيانات (الجداول، العروض، الإجراءات المخزنة)
│   └── 02_SampleData.sql      بيانات تجريبية اختيارية
└── AssetTracking/
    ├── UI/                    الواجهة: Forms (النوافذ) و Pages (الصفحات) — كل شاشة .cs + .Designer.cs
    ├── BLL/                   المنطق: التحقق، قواعد العمل، الصلاحيات
    ├── DAL/                   الوصول للبيانات: ADO.NET واستعلامات ببارامترات
    ├── Reports/               محرك الطباعة وقائمة التقارير والمحاضر
    ├── Security/              الجلسة والأدوار وتشفير كلمة المرور
    └── Common/                الإعدادات والألوان والنصوص العربية
```

**ملاحظات:**
- القيمة الدفترية والإهلاك لا يُخزَّنان؛ يُحسبان عند العرض من `vw_AssetValuation`.
- لا حذف نهائي: الأصل يُؤرشف، والقسم/الموقع/الشخص/المستخدم يُعطَّل.
- تصدير PDF يستخدم طابعة Windows المدمجة **Microsoft Print to PDF**.
